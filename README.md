# mango_inference_test

Mango Inference와 OpenRouter의 관측 성능·비용 및 라우팅을 비교하는 실험입니다.

- **현재 기준:** [프로토콜 v1.0](docs/02_실험_프로토콜.md)(1회 실험, [0절 변경표](docs/02_실험_프로토콜.md#0-v10-변경-1회-실험-2026-11-17), 설정 `code/config/run1.yaml`, 예상 약 $36·상한 $50). 이전 기준 v0.9.4 · [통합 명세 HTML](pdf/04_통합명세_v0.9.2.html)(파일명은 v0.9.2, 내용은 v0.9.4). 파일럿 결과로 v1.0을 정했습니다.
- **상태:** 간이 테스트·reasoning 시험 완료. 측정 코드 작성 완료([실행 절차](code/RUN.md)). 측정 VM(AWS 서울 m6i.large)에서 측정기 검증 통과(시각 오차 중앙값 0.3ms, 300초 마감 정확). **2026-11-17 파일럿 완료**([결과와 결론](docs/08_파일럿_결과.md)): 본 루프 1,556건, Broadcast 켬·끔 대조 160건, 결합률 100%, Mango 청구 대조 0.1% 일치. 파일럿 후 수정·결정 사항(실패 분류, 키 로딩, W2 세션 수, 추론 폭주 처리, 예산)은 v1.0 0절에 반영했습니다. **2026-11-17 23:50~11-18 03:02 KST 1회 실험 실행**([결과](docs/09_1회실험_결과.md)): 4,528건, 결합률 100%, 확증 판정 12개 중 Mango 우위 5·열위 2·판정 불가 5(그 시간대 1회 결과).
- **1회 실험 이후 분석(2026-11-18):** [OpenRouter 공개 통계 분석](docs/10_OpenRouter_공개통계_분석.md)(점유율을 최근 1주로 집계, 성능·가격·오류율과 점유율의 상관, 신규 모델 지원 시점, 공식 개발사 사례, 공개 기준 Mango 위치, 가격 민감도). [1회 결과](docs/09_1회실험_결과.md) 11절에 **OR-고정 대상 선정 오류**(30일 점유율·수집 누락), 12절에 정책별 트래픽 비중 추정을 추가했습니다. 다음 회차 안은 [2회 실험 설계 초안](docs/11_2회실험_설계_초안.md)(미확정)입니다. 발표 자료와 3D 그래프는 [slides/](slides/README.md)에 있습니다.
- **파일럿 예비 관측(판정 아님, 1회 실험으로 대체):** 아래 캐시 관련 관측은 1회 실험에서 `session_id`를 보내자 사라져 클라이언트 설정 차이로 확인됐습니다([1회 결과](docs/09_1회실험_결과.md) 3절). 첫 토큰(추론 포함)은 네 모델 모두 Mango가 약 30% 빨랐습니다. 답변 첫 토큰의 차이는 대부분 decode 속도에서 왔습니다(DeepSeek·GLM-5.3 Flash에서 큰 차이, Kimi K3.1 Pro는 Mango decode가 더 느림). 세션 비용은 Mango 정가가 높은 모델(DeepSeek, GLM-5.3)에서 불리하고, OR-기본이 1턴과 2턴을 다른 제공사로 보내 캐시를 놓치는 만큼 Mango에 유리합니다. GLM 계열은 양쪽 모두에서 추론 폭주(32,768토큰 상한 도달)가 나왔습니다.
- **판정:** P1·P2·P4 × 4모델의 12개 주 판정. P3는 성공률 차이 추정만 수행. 품질 점검 Q는 v1.0에서 25문항 × M·OR-기본으로 줄여 기술 통계만 보고합니다(v0.9.4의 400문항 × 7경로는 미실행).
- **규모(v1.0 1회 실험):** 1회차, 모델당 1,132건 × 4모델 = 4,528건 + Q 200건. W1·W3 각 40쌍, W2 40세션. 예상 약 $36·상한 $50, 실제 약 $38(OpenRouter $19.6 + Mango $18.4). 판정은 그 시간대(한국 새벽) 1회에 대한 결론이며 다른 시간대·날로 일반화하지 않습니다. v0.9.4의 하루 4개 시점 설계(약 25,600건, 서울 약 $107~229)와 미국 축소판은 실행하지 않았습니다.
- **2026-11-19 추가:** [OpenRouter DeepSeek 시간·지역 분석](docs/12_OpenRouter_DeepSeek_시간지역_분석.md) — 성능 화면 모든 필터 조합 4,065건 수집. 같은 제공사 기준 처리량은 위치와 무관하고, 첫 토큰은 서울이 미국보다 약 26% 늦음(성능 차이 중 제공사 59%, 사용자 위치 5.5%, 시간대 0.2% 설명). 서버 위치는 공개 자료로 특정되지 않음. 대시보드 두 개(시간·지역, 1회 실험)를 독립 HTML로 실었습니다.
- **해석:** 서울에서 관측한 종단간 성능과 고정 대화 재생의 프로토콜 성공률입니다. 서버 내부 성능·실제 에이전트 과제 성공률로 일반화하지 않습니다.

## 검증과 실행

```bash
python -m unittest discover -s code -p "test_*.py"
python code/verify_meter.py --out meter_check.json   # 모의 서버, 과금 없음
python code/smoke_test.py --dry-run
```

간이 테스트는 본 runner가 아닙니다. 실제 호출은 과금됩니다. 키는 환경변수 `MANGO_API_KEY`, `OPENROUTER_API_KEY` 또는 저장소 밖 `%USERPROFILE%\mango_bench.env`에서 읽습니다.
