# mango_inference_test

Mango Inference와 OpenRouter의 관측 성능·비용 및 라우팅을 비교하는 실험입니다.

- **현재 기준:** [프로토콜 v0.9.4](docs/02_실험_프로토콜.md) · [통합 명세 HTML](pdf/04_통합명세_v0.9.2.html)(파일명은 v0.9.2, 내용은 v0.9.4). 설계는 확정했고, 파일럿으로 회차당 횟수·Q 범위·W2 세션 수를 정한 뒤 v1.0으로 동결합니다.
- **상태:** 간이 테스트·reasoning 시험 완료. 측정 코드 작성 완료([실행 절차](code/RUN.md)). 측정 VM(AWS 서울 m6i.large)에서 측정기 검증 통과(시각 오차 중앙값 0.3ms, 300초 마감 정확). **2026-11-17 파일럿 완료**([결과와 결론](docs/08_파일럿_결과.md)): 본 루프 1,556건, Broadcast 켬·끔 대조 160건, 결합률 100%, Mango 청구 대조 0.1% 일치. v1.0 동결 전 수정·결정 사항(실패 분류, 키 로딩, W2 48세션, 추론 폭주 처리, 예산)이 남아 있습니다. 본 측정 미실행.
- **파일럿 예비 관측(판정 아님):** 첫 토큰(추론 포함)은 네 모델 모두 Mango가 약 30% 빨랐습니다. 답변 첫 토큰의 차이는 대부분 decode 속도에서 왔습니다(DeepSeek·GLM-5.3 Flash에서 큰 차이, Kimi K3.1 Pro는 Mango decode가 더 느림). 세션 비용은 Mango 정가가 높은 모델(DeepSeek, GLM-5.3)에서 불리하고, OR-기본이 1턴과 2턴을 다른 제공사로 보내 캐시를 놓치는 만큼 Mango에 유리합니다. GLM 계열은 양쪽 모두에서 추론 폭주(32,768토큰 상한 도달)가 나왔습니다.
- **판정:** P1·P2·P4 × 4모델의 12개 주 판정. P3는 성공률 차이 추정만 수행. Q는 M·OR-기본·고정 5곳의 7경로, 400문항으로 품질 허용 범위를 확인합니다.
- **규모:** 측정일은 하루(6시간 간격 4개 시점)입니다. W2 32세션 기준 약 25,600건, 서울 약 $107~229, 상한 $250(파일럿 기준 재추정 약 $270~300, 동결 전 재계산). W2를 48세션으로 늘려도 최대 약 $15 추가라 상한 안입니다. 판정은 측정한 날의 4개 시점에 대한 결론이며, 다른 날 재실행은 따로 분석해 방향 일치만 봅니다. 가장 큰 예산 위험은 Q의 reasoning 출력 길이라 파일럿에서 재계산합니다. 미국 축소판은 별도 예산 확정 전 미실행.
- **해석:** 서울에서 관측한 종단간 성능과 고정 대화 재생의 프로토콜 성공률입니다. 서버 내부 성능·실제 에이전트 과제 성공률로 일반화하지 않습니다.

## 검증과 실행

```bash
python -m unittest discover -s code -p "test_*.py"
python code/verify_meter.py --out meter_check.json   # 모의 서버, 과금 없음
python code/smoke_test.py --dry-run
```

간이 테스트는 본 runner가 아닙니다. 실제 호출은 과금됩니다. 키는 환경변수 `MANGO_API_KEY`, `OPENROUTER_API_KEY` 또는 저장소 밖 `%USERPROFILE%\mango_bench.env`에서 읽습니다.
