# 2회 실험 설계 초안 (2026-11-18, 미확정)

[프로토콜 v1.0](02_실험_프로토콜.md)의 1회 실험([09번](09_1회실험_결과.md)) 뒤에 바꿀 점을 모았습니다. **초안이며 일정과 예산은 정해지지 않았습니다.** 실행 전에 프로토콜 새 버전으로 동결하고, 0절 변경표와 13절 이탈·검토 기록에 남깁니다. 판정 지표(P1·P2·P4, Mango ÷ OR-기본)와 판정 규칙은 1회와 같게 둡니다. 그래야 회차 간 방향 일치를 볼 수 있습니다.

## 1. OR-고정 대상 선정 규칙 (1회 설계 오류 수정)

1회의 고정 5곳은 2026-11-16 수집본의 30일 점유율로 골랐습니다. 그런데 신규 모델의 진입 시점 차이와 수집 누락(Kimi 미귀속 8.2%, Alibaba 누락) 때문에 최근 상위 제공사를 대표하지 못했습니다([09번 11절](09_1회실험_결과.md), [10번 1절](10_OpenRouter_공개통계_분석.md)).

| 항목 | 규칙 |
|---|---|
| 점유율 기간 | 실행 직전 **완료된 최근 7일** 토큰 점유율(제공사 단위). 30일 창은 쓰지 않음 |
| 수집 품질 | 모델 전체 토큰 대비 미귀속 **5% 이하**인 수집본만 사용. 넘으면 제공사 페이지로 보충 수집 후 다시 계산 |
| 선정 | 1주 점유율 상위 5개 제공사. 공식 개발사가 5위 밖이어도 표시만 하고 넣지 않음 |
| 대표 엔드포인트 | 제공사 안에서 표준 등급(Fast·Flex·Priority 등 제외) 중 **1일 토큰 비중 최대**. 1회는 가격 표본 토큰을 대리 지표로 썼음 |
| 동결 | 선정 결과·수집 시각·점유율 파일을 실행 전에 기록하고, 실행 중에는 바꾸지 않음 |
| 1회와의 연결 | 1회 고정 대상과 겹치는 엔드포인트는 회차 간 비교. 바뀐 곳은 사유와 함께 기록 |

**잠정 선정 (2026-11-10~11-16 점유율, [share_7d.csv](../data/openrouter_recollect_20261117/share_7d.csv)).** 실행 직전에 같은 규칙으로 다시 계산해 확정합니다.

| 모델 | 미귀속 | 고정 대상 (1주 점유율) | 1회 대비 |
|---|---:|---|---|
| Kimi K3.1 Pro | 0.3% | `alibaba` 21.9% · `inference-net/mxfp4` 14.5% · `wafer/us` 12.7% · `moonshotai/mxfp4` 12.7% · `modal/mxfp4` 8.3% | Alibaba 추가, Together 제외 |
| GLM-5.3 | 3.4% | `wafer/us` 21.9% · `inference-net/fp4` 19.5% · `decart/fp4` 11.2% · `z-ai/fp8` 8.3% · `together` 5.4% | Together 추가, SiliconFlow 제외. inference.net 대표가 `/us` → `/fp4` |
| GLM-5.3-Flash | 4.4% | `together` 16.0% · `inference-net/us` 7.7% · `coreweave/nvfp4` 7.0% · `z-ai/fp8` 7.0% · `cohere/nvfp4` 6.4% | Cohere 추가, Open Inference 제외 |
| DeepSeek V4.1 Flash 1017 | 0.2% | `deepseek` 20.0% · `deepinfra/fp8` 15.3% · `wafer/us` 7.9% · `together` 7.7% · `inference-net/us` 6.4% | 같음 |

5위와 6위의 차이가 작습니다. GLM-5.3-Flash는 Cohere 6.4% 대 Particle AI 5.6%, DeepSeek은 inference.net 6.4% 대 Relace 5.4%입니다. 재계산에서 순위가 바뀌면 바뀐 대로 따릅니다.

## 2. 1회 한계에 대한 보완

| 1회 한계 | 2회 보완(안) | 근거 |
|---|---|---|
| 한국 새벽 한 시간대만 측정 | 미국 업무 시간대를 포함해 하루 여러 시점. 같은 설정으로 다른 날 반복 | [09번](09_1회실험_결과.md) 머리말 |
| 지리 효과(서울 VM, OR 제공사는 대부분 미국) | 미국 동부 VM 추가(프로토콜의 미국 축소판: M·OR-기본 × W1·W2) | 09번 8절 |
| 긴 입력에서 M의 첫 토큰 우위가 줄어드는 신호(32k, 모델당 1건) | 입력 길이 1k·10k·32k 이상을 길이별로 여러 건. OpenRouter 실사용은 입력 97~99%, 캐시 적중 83~93%의 긴 맥락 작업이 대부분 | 09번 9절, [model_summary.csv](../data/openrouter_recollect_20261117/model_summary.csv) |
| W2 40세션이라 동등 판정이 어려움 | W2 세션 수 확대(프로토콜 2-3절의 상한 48 이상, 예산 확인 후) | 09번 2절 |
| 신뢰성(가용성) 지표 없음 | OpenRouter 엔드포인트별 가용성(uptime)·오류 화면 수집을 실행 전후에 추가. M은 실행 중 실패율로 대조 | [10번 2절](10_OpenRouter_공개통계_분석.md) |
| 정책별 비중 추정의 신뢰도 낮음 | 기본 라우팅 첫 시도 표본을 여러 시간대 1,000건 이상(짧은 요청). 가능하면 두 번째 계정 | 09번 12절 |
| 품질 점검 25문항은 판정용 아님, 추론 설정이 양쪽 다름 | 문항 확대(원래 계획 400), 반복 샘플, 양쪽 추론 설정 명시, OR-고정 경로 포함 | 09번 10절 |
| Mango 할인·판매 시작일 미확인 | 실행 직전 `GET /v1/models` 단가와 콘솔 청구로 할인 적용 여부 확인. 모델별 판매 시작일 확인 | 10번 3·6절 |

## 3. 비용 기준

1회 실험은 본 루프 4,528건에 약 $38(OpenRouter $19.6, Mango $18.4)이 들었습니다(09번 6절). 2회는 위 보완 범위에 따라 다시 산정합니다. 시간대·지역을 늘리면 그만큼 배수로 늘어납니다.
