# OpenRouter DeepSeek V4.1 Flash 1017: 시간·지역별 제공사 통계 (2026-11-19)

OpenRouter 성능 화면의 모든 필터 조합을 받아, 시간·관측 위치·추론 강도·백분위에 따라 제공사 성능이 어떻게 달라지는지, 그리고 **사용자 위치가 성능을 얼마나 바꾸는지**를 정리했습니다.

- **대시보드:** [slides/시간지역_성능_대시보드.html](https://drive.google.com/file/d/1IQx14rWnMmHegCraLTzxMXjFoS2hZCOv/view?usp=drivesdk)(내려받아 브라우저로 열기, d3는 CDN에서 불러옴)
- **자료:** [results/openrouter_deepseek_20261119](../results/openrouter_deepseek_20261119/README.md)
- **관측이지 실험이 아닙니다.** 제공사마다 요청 구성(입력·출력 길이)이 통제되지 않았고, 인과로 해석하지 않습니다.

## 1. 수집

- 대상: `deepseek/deepseek-v4.1-flash-20261017`(standard 변형) [성능 화면](https://openrouter.ai/deepseek/deepseek-v4.1-flash-1017#performance)
- 시각: 2026-11-19 00:51:40~00:57:17 UTC. 페이지가 쓰는 공개 프런트엔드 통계 API를 호출했고, 화면 수치와 일치함을 대조했습니다.
- 범위: 관측 위치 27곳(모든 위치 + 화면의 25곳 + API 목록에만 있던 DEN) × 추론 강도 5 × 백분위 5 × 기간 2 × 성능 3지표(처리량·TTFT·E2E) = 4,050건, 기타 지표 15건. **4,065건 수신, 실패 0.** 관측값 3,656,374개, 엔드포인트 50개.

## 2. 집계 방식

1. **3일 = 1시간 격자(73칸), 1주 = 1일 격자(8칸).** 마지막 칸(11-19 00:00 UTC)은 수집 시점에 진행 중이던 시간입니다.
2. **관측이 없는 시간은 칸 자체가 빠집니다.** 그래서 관측률은 반환된 칸 수가 아니라 전체 격자(73·8)로 나눴습니다.
3. API 응답은 CDN에 1시간 캐시됩니다(`max-age=3600`). 1시간 단위 집계와 맞지만, 매시 정각 갱신의 증거는 아닙니다.
4. **도구 호출 오류율·구조화 출력 오류율·캐시 적중률은 지역·추론 강도 필터가 적용되지 않습니다.** 화면에서 지역을 골라도 전 세계 값입니다.
5. 관측 위치(colo)는 요청이 OpenRouter에 들어온 지점입니다. 제공사 GPU 위치가 아닙니다.
6. 평균은 시간별 대표값의 단순평균입니다. 요청 수 가중이 아닙니다. 처리량의 P90·P99는 느린 쪽 꼬리입니다.

## 5. 사용자 위치가 성능을 얼마나 바꾸나

같은 엔드포인트를 27개 위치에서 잰 값이므로, 엔드포인트를 고정하고 사용자 위치만 바꾼 비교가 들어 있습니다. 3일 시간별 값(약 5.7만 개, 진행 중인 마지막 시간 제외)에 log(값) = 엔드포인트 + 관측 위치 + 시각(KST) 가법 모형을 맞췄습니다. 결과는 [location_effect_20261119.json](../results/openrouter_deepseek_20261119/location_effect_20261119.json)입니다.

| 지표 | 엔드포인트가 설명 | 관측 위치가 설명 | 시각이 설명 | 서울 ÷ 미국 12곳(같은 엔드포인트) |
|---|---:|---:|---:|---:|
| 처리량 | 59% | 1~2% | 0.4% | 0.97배 |
| TTFT | 59% | 5.5% | 0.2% | 1.26배 |
| E2E | 34% | 3~4% | 0.3% | 1.29배 |

- **처리량은 위치와 무관합니다.** 거리는 일정한 지연을 더할 뿐 토큰 생성 속도를 바꾸지 않습니다.
- **TTFT는 위치 영향이 있지만 제공사 차이의 약 1/10입니다.** 관측 위치 배율은 피닉스 0.71 ~ 뭄바이 1.43, 미국 평균 0.88, 유럽 1.06, 서울 1.10, 도쿄 1.14, 싱가포르 1.16. 서울은 같은 제공사라도 미국보다 첫 토큰이 약 26%(TTFT 중앙값 0.9초 기준 약 0.2초) 늦고, 이는 태평양 왕복 1~2회 크기입니다.
- **시간대 효과는 ±5% 안**입니다.
- 사용자 단말~OpenRouter 구간은 포함되지 않습니다.

## 6. 서버 위치는 공개 자료로 특정되지 않습니다

엔드포인트 50개의 서버 위치를 OpenRouter 신고값(데이터센터 국가·본사)과 웹 공개 자료, API 주소의 DNS·소속 네트워크로 조사했습니다([endpoint_locations_research_20261119.csv](../results/openrouter_deepseek_20261119/endpoint_locations_research_20261119.csv)). 기준은 "한 곳으로 특정되는 것만, 작은 나라는 국가만으로 인정, 미국·중국 같은 큰 나라는 국가만으로 불인정"입니다.

- **도시 하나로 특정되는 엔드포인트는 없습니다.** 47개는 여러 지역 운영 또는 위치 비공개로 제외했습니다.
- 지역까지 좁혀지는 곳은 Inceptron(핀란드)과 Ant Digital(싱가포르·말레이시아) 둘이지만, 3일 관측이 지역당 1~16시간뿐입니다. DekaLLM은 인도네시아(Lintasarta 자체 네트워크)로 근거가 가장 강하지만 도시는 확인하지 못했습니다.
- **한 엔드포인트 뒤에 여러 지역의 서버가 있는 것이 일반적입니다.** Fireworks는 서버리스 요청을 30여 지역에 자동 배분하고, Cloudflare는 180여 도시 중 가까운 곳으로 보내며, Alibaba 싱가포르 지역은 중국 본토 밖 여러 노드에서 추론합니다. API 주소 44개 중 15개는 Cloudflare, 17개는 Google·AWS·Azure 접속점이라 IP로는 GPU 위치를 알 수 없습니다(서울에서 조회).
- 따라서 5절의 '엔드포인트 효과' 안에 서버 위치 효과가 섞여 있고 분리할 수 없습니다. 분리하려면 지역을 고정할 수 있는 같은 서비스를 두 곳 이상의 사용자 위치에서 재는 실측이 필요합니다.

## 7. 한계

- 공개 API의 시간별 대표값만 볼 수 있고 요청 수는 제공되지 않습니다. 관측률은 '그 시간에 값이 있었는지'일 뿐 트래픽 양이 아닙니다.
- 1회 수집 스냅숏입니다. 1시간 뒤에는 3일 창이 한 칸 이동합니다.
- 원본 API 응답(약 21MB)과 수집·분석 코드는 이 저장소에 싣지 않았습니다. 대시보드 HTML 안에 P50·전체 강도의 지역·제공사별 시계열 전체가 들어 있습니다.
