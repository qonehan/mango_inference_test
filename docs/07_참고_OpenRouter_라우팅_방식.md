# OpenRouter 제공사 라우팅 방식 정리

작성일: 2026-11-16. 관련: [실험 프로토콜](02_실험_프로토콜.md)

OpenRouter 공식 문서 두 개를 읽고, 한 요청이 어느 제공사로 가는지를 **기본 자동 배분**과 **사용자 지정**으로 나눠 정리했습니다. 두 페이지 모두 갱신일 표시가 없어 확인일(2026-11-16)만 적습니다. 원문을 복제하지 않고 요약했습니다.

| 출처 | 다루는 내용 |
|---|---|
| [Traffic Routing](https://openrouter.ai/docs/guides/providers/traffic-routing) | OpenRouter가 직접 고를 때 엔드포인트별 트래픽 몫을 정하는 방식 (제공사 관점) |
| [Provider Routing](https://openrouter.ai/docs/guides/routing/provider-selection) | 요청의 `provider` 객체·단축 접미사·계정 설정·BYOK로 사용자가 제어하는 방식 |

## 1. 요약

- **기본값은 가중 무작위 배분입니다.** 게시가가 아니라 실효 가격에 속도·첫 토큰 시간·오류·429·도구 호출 품질을 더한 "보정 가격"으로 몫을 정하고, 요청마다 몫에 비례해 무작위로 뽑습니다.
- **1등 근처면 대부분을 나눠 받고, 경쟁 가장자리 밖은 급감합니다.** 다만 0은 아니어서 개선을 감지할 탐색 트래픽은 계속 받습니다.
- **기본 배분을 건너뛰는 경우는 네 가지입니다.** `sort`(요청 또는 계정 기본값), `:floor`/`:nitro`, `order`, 자기 제공사 키(BYOK). `only`/`ignore`는 남는 제공사가 2곳 이상이면 그 안에서 여전히 기본 배분을 씁니다.
- **공개 통계로는 두 경로의 비율을 나눌 수 없습니다.** 문서도 비율을 공개하지 않습니다. 월간 제공사 통계([data](../data/openrouter_monthly_share_final_20261116.csv))의 점유율은 두 경로가 섞인 결과입니다.

## 2. 요청 한 건의 경로

```
요청 ─▶ ① 후보 거르기 (계정 설정 + 요청 필터)
         계정 허용·제외 목록, 데이터 정책·ZDR, only/ignore,
         require_parameters, quantizations, max_price, 도구·출력 길이 지원
      ─▶ ② 순서 정하기
         ├─ sort · :floor · :nitro · order · BYOK 있음 ─▶ 지정한 순서대로 시도
         └─ 없음 ─▶ 기본 배분: 보정 가격으로 몫 계산 → 가중 무작위 선택
      ─▶ ③ 실패 시 남은 후보에서 같은 방식으로 재선택 (allow_fallbacks=false면 중단)
```

프롬프트 캐시가 따뜻한 동안 후속 요청은 같은 제공사에 머뭅니다.

## 3. 기본 자동 배분 (Traffic Routing)

### 3-1. 입력 지표

모두 최근 실제 트래픽에서 측정하며 최근 몇 분의 비중이 가장 큽니다. 트래픽이 적은 엔드포인트는 비슷한 제공사의 평균값에서 시작합니다.

| 지표 | 정의 | 보정 가격 반영 (문서 예시) |
|---|---|---|
| 실효 가격 | 최근 30분 실제 청구액. 캐시 적중률·입출력 비율 반영 | 요청당 예상 토큰 × 실효 단가 (약 $0.142) |
| 속도 | 첫 토큰 대기를 포함한 초당 출력 토큰 | 5초 대기 + 5초간 500토큰 = 50 tok/s |
| 첫 토큰 시간(TTFT) | 첫 토큰까지의 시간 | 속도와 별도로 가격에 직접 가산 (대화형·에이전트 용도) |
| 신뢰성 | 엔드포인트 탓의 실패 | 오류율 1% × 페널티 8배 ≈ 가격 +8% |
| 품질 | 형식이 올바른 도구 호출 응답 비율 | 95%면 가격 약 +5% |
| 429 | 거절 후 다른 곳으로 재전송하는 대기 | 대기 비용+페널티를 429 비율로 가중 ($2.50 × 0.4% ≈ +$0.01) |

| 신뢰성 오류로 셈 | 세지 않음 |
|---|---|
| 5xx, 응답 없음(연결 끊김·타임아웃), 설정 오류(401·402·404·405·408·410·421·423·424·426·498), 중간 실패 | 400·413·422, 지역·법적 차단(403·451), 사용자 종료(499), 429(별도 계산) |

### 3-2. 안전장치

- **차단:** 신뢰성·품질·429가 같은 모델의 다른 제공사보다 훨씬 나쁘면 회복할 때까지 트래픽 0.
- **단기 후퇴:** 429 급증·지연 급등 시 그동안 몫을 잠시 낮춤.
- **용량 학습:** 429가 나기 전에 제공사별 용량을 학습해 넘치는 몫을 다른 곳으로 보냄.
- **품질 표시:** 도구 호출이 깨졌거나 벤치마크 정확도가 기대보다 크게 낮으면 표시가 풀릴 때까지 탐색 트래픽만.

수치 공식(예: 가격의 역제곱 가중)은 두 문서 어디에도 없습니다. 몫 곡선은 정성적으로만 설명돼 있습니다.

## 4. 사용자 제어 (Provider Routing)

### 4-1. `provider` 객체 필드

| 필드 | 기본값 | 효과 | 분류 |
|---|---|---|---|
| `order` | - | 제공사 슬러그를 순서대로 시도. 이름 붙인 제공사에선 BYOK 우선순위보다 앞섬 | 순서 지정 (기본 배분 우회) |
| `allow_fallbacks` | true | false면 지정한 곳 외 예비 제공사 사용 안 함. `order` 없이 false면 1순위 엔드포인트만 | 폴백 |
| `sort` | - | `"price"`·`"throughput"`·`"latency"` 또는 `{by, partition}` | 순서 지정 (기본 배분 우회) |
| `only` / `ignore` | - | 허용·제외 슬러그 | 필터 (2곳 이상 남으면 기본 배분 유지) |
| `require_parameters` | false | true면 요청 파라미터를 모두 지원하는 제공사만 | 필터 |
| `data_collection` | "allow" | "deny"면 사용자 데이터를 수집하지 않는 제공사만 | 필터 |
| `zdr` | - | true면 ZDR 엔드포인트만 (Safety Retention 엔드포인트도 허용, 단 계정·가드레일이 "ZDR only"면 제외) | 필터 |
| `enforce_distillable_text` | - | true면 모델 작성자가 텍스트 증류를 허용한 모델만 | 필터 |
| `quantizations` | - | 양자화 수준 필터 (int4·int8·fp4·fp8·fp16·bf16 등) | 필터 |
| `max_price` | - | 100만 토큰당 `prompt`·`completion` 상한 (선택: `request`, `image`). 맞는 가격이 없으면 요청 실행 안 함 | 필터 (하드) |
| `preferred_min_throughput` | - | tok/s 하한. 숫자는 p50, 객체는 p50·p75·p90·p99 | 선호 (소프트) |
| `preferred_max_latency` | - | 초 단위 상한. 위와 동일 | 선호 (소프트) |

선호 조건은 최근 5분 이동 창의 모델·제공사별 백분위로 판단합니다. 미달 엔드포인트는 **제외되지 않고 목록 끝으로** 밀립니다. 조건을 여러 개 주면 모두 충족해야 우선 그룹에 듭니다.

### 4-2. 정렬과 단축 접미사

| 방법 | 동작 |
|---|---|
| `sort: "price"` / `"throughput"` / `"latency"` | 최저가 / 최고 처리량 / 최저 지연 순서로 시도 |
| `sort: {by, partition: "model"}` (기본) | 폴백 모델이 있어도 1순위 모델의 엔드포인트를 먼저 시도 |
| `sort: {by, partition: "none"}` | 나열한 모든 모델의 엔드포인트를 한 줄로 정렬 |
| `모델:floor` | 가격 정렬 + flex 서비스 등급 엔드포인트 포함 |
| `모델:nitro` | 처리량 정렬 + priority 서비스 등급 엔드포인트 포함 |

### 4-3. 엔드포인트 지정

- 슬러그 형식은 `provider[/variant][/region][/tier]`입니다. 기본 슬러그(`google-vertex`)는 그 제공사의 변형·리전 엔드포인트를 모두 포함하고, 구체 슬러그(`deepinfra/turbo`)는 하나만 지정합니다.
- 기본 슬러그만으로는 서비스 등급 엔드포인트(`openai/fast`, `google-vertex/flex` 등)에 들어가지 않습니다. `service_tier`나 접미사 슬러그가 필요합니다. 오픈웨이트 모델의 priority 엔드포인트는 예외로 기본 풀에 있습니다.
- 비공개 엔드포인트: `order`를 주고 `allow_fallbacks: false`면 `order` 제공사 → 자기 비공개 엔드포인트 → (다른 공개 제공사 없음) 순서입니다.

### 4-4. 계정 설정과 요청 설정의 관계

| 계정 설정 (`/settings/preferences`, `/settings/privacy`) | 요청 설정과의 관계 |
|---|---|
| 기본 제공사 정렬 | 설정하면 기본 배분 우회. 요청 `sort`가 이를 덮어쓰는지는 문서에 없음 |
| 허용 제공사 | API·채팅방 전체에 적용. 요청 `only`는 이 범위 안에서만 좁힘. 교집합이 없으면 404 |
| 제외 제공사 | 요청 `ignore`와 합집합 |
| 데이터 정책 | `data_collection`의 계정 단위 버전 |
| ZDR (모델 그룹별 또는 가드레일) | 요청 `zdr`과 OR. 요청으로 켤 수는 있어도 계정·가드레일 설정을 끌 수는 없음 |

### 4-5. BYOK와 기타

- 자기 키가 있는 제공사는 `order`가 없으면 자동 우선입니다. `order`가 있으면 그 순서를 따르되 각 제공사 안에서 자기 키를 공유 용량보다 먼저 씁니다.
- `require_parameters: false`일 때도 도구, 응답 형식(구조화 출력 포함), verbosity는 소프트 선호로 작동합니다. 일부 제공사만 지원하면 그곳으로만 가고, 아무도 지원하지 않으면 파라미터를 무시합니다.
- 리전 데이터 보관은 Business·Enterprise 전용으로, `eu.openrouter.ai` 또는 `us.openrouter.ai` 주소로 보냅니다.
- 문서에 없는 것: 프리셋 설명, 모델 폴백(`models`) 상세(별도 페이지), 계정 정렬과 요청 정렬의 충돌 규칙.

## 5. 기본 배분이 적용되는 범위

| 경로 | 기본 배분 | 근거 |
|---|---|---|
| 아무 설정 없음 | 적용 | 두 문서 |
| `only`/`ignore`/데이터 정책 등 필터 후 2곳 이상 남음 | 남은 후보 안에서 적용 | Provider Routing |
| 필터 후 1곳만 남음 | 미적용 (그곳으로) | Traffic Routing |
| `order` 지정 | 미적용 | 두 문서 |
| `sort`(요청 또는 계정 기본값), `:floor`, `:nitro` | 미적용 | 두 문서 |
| BYOK | 미적용 | 두 문서 |
| `preferred_*` 선호 조건 | 문서상 명시 없음. 미달 엔드포인트를 뒤로 미는 정렬로 설명됨 | Provider Routing |
| 모델 라우터(Auto Router 등) | 별도 계층. 모델을 고른 뒤 제공사 선택은 위 규칙을 따른다고 추정 (문서 미확인) | - |

## 6. 남은 확인

- 기본 배분과 사용자 지정의 실제 트래픽 비율은 공개되지 않았습니다. OpenRouter 문의나 고객 인터뷰가 필요합니다.
- OpenRouter 사용자 이용방식 조사(공개 글 기반) 6절의 직접 호출 실험(기본, `sort: price`, `order` 고정, 프리셋 비교)으로 같은 모델에서 어느 제공사가 선택되는지 기록할 수 있습니다. 아직 실행하지 않았습니다.
- 모델 폴백, 서비스 등급, 프리셋, 가드레일 페이지는 이번에 읽지 않았습니다.
